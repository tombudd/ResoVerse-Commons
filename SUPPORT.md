# Support

## Questions and early ideas

Use [GitHub Discussions](https://github.com/tombudd/ResoVerse-Commons/discussions)
for setup questions, design exploration, and ideas that are not yet actionable
issues. Search existing conversations before opening a new one.

## Bugs and proposals

Use the structured [issue chooser](https://github.com/tombudd/ResoVerse-Commons/issues/new/choose)
for reproducible bugs, capability proposals, and evaluation fixtures. Include
the smallest public example that demonstrates the problem.

Maintainers aim to acknowledge new questions and contributions within five
working days. This is a response target, not a guarantee of resolution or
acceptance.

## Security vulnerabilities

Do not disclose exploit details in a public issue or Discussion. Follow the
private process in [Security](SECURITY.md).

## Conduct reports

Follow the private reporting instructions in the [Code of
Conduct](CODE_OF_CONDUCT.md). Do not publish sensitive incident details.

## Boundaries

This project cannot provide support for private UNA systems, production
credentials, customer environments, private evidence, or requests to bypass a
`HOLD`. Public support does not grant runtime, admission, learning, memory, or
deployment authority.

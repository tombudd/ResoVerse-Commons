# Roadmap

The roadmap communicates direction, not guaranteed delivery dates. A roadmap
item grants no runtime, admission, or production authority.

## Available now — observed

- V1 capability-manifest and bundle contracts
- Fail-closed Python validation with stable receipts
- Byte binding, root containment, and Draft 2020-12 schema checks
- Safe and adversarial examples
- Independent public-boundary review
- Trusted-main verification
- Portable cross-language conformance corpus and runner
- Supported-version and operating-system CI matrix
- Clean wheel-build and installation smoke test
- Dependabot configuration and documented release trust path
- Experimental zero-dependency JavaScript validator passing the shared corpus

## Community foundation — designed

- A five-minute contributor path
- Structured capability, fixture, and bug proposals
- Non-executing pull-request boundary feedback
- Public Discussions for questions and early designs
- A maintained queue of bounded starter issues
- Clear acknowledgement and review expectations

## Next protocol work — aspired

- Bundle-generation and inspection commands
- More adversarial fixtures and reason-code coverage
- Promote the JavaScript validator after raw duplicate-key and adversarial parity
- Transparent candidate-registry and revocation procedures
- Reviewer guidance and reproducible evaluation packets

## Not on the public roadmap

- Automatic ingestion or learning from contributions
- Publication of private runtime, memory, identity, or governance internals
- Contributor code execution in pull-request automation
- Self-authorization or self-issued independent review
- Production deployment from this repository

Propose roadmap changes through a capability-proposal issue or a Discussion.
Maintainers will state whether a proposal is accepted for exploration, held for
missing evidence, or outside the public boundary.
